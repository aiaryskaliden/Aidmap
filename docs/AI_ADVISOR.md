# AidMap Admissions Advisor

Maple, the Advisor at /advisor, uses AidMap’s source-linked undergraduate catalogue. It recognizes admissions, funding and writing questions in English, Russian and Kazakh. It uses the language of each question and the workspace language for ambiguous short queries. A turn opens with a focused reply plus expandable comparison, next steps and grouped official sources. Each fact carries a verification status, cycle and scope when available. University names and source excerpts may use their original language.

## How matching works

A university name can answer Maple’s clarifying question about a test or deadline. In the same conversation, a follow-up about ACT, TOEFL, IELTS or Duolingo uses the last university. TOEFL figures retain the source’s scale, test date and distinction between minimum and recommended scores. A score explicitly typed in the current question takes precedence over the attached profile for that turn.

Questions asking for published student profiles or essay examples open the corresponding reading library. The chat supplies a navigation link; the library checks access when the reader opens a guide.

- Explicitly selected universities are shown even when a fact or funding category is missing. Otherwise the search filters by programme, destination and requested funding type. A new school or country in a question can take precedence. A follow-up can reuse the previous intent, focused topic and university IDs.
- The budget check compares documented annual cost in the same currency. Published tuition alone can establish a lower bound, and last cycle’s prices are shown as historical references. Unpublished costs and scholarship contributions leave the final amount open. Funding distinguishes full tuition, full cost of attendance and demonstrated need.
- Reach flags a published SAT gap and may refer to a historical cohort. Target requires a programme match, a comparable published test minimum and an annual cost within budget. Safety candidates have verifiable programme and budget evidence and a published SAT policy that does not use SAT. Schools remain unclassified when those signals are unavailable. Qualification, GPA, selection and award outcomes require review of the institution’s terms.
- The public chat streams a focused answer, comparison or plan from the catalogue as newline-delimited JSON. An authorized adult demo can append a brief model-written coaching suggestion for the synthetic scenario. It receives the explicitly consented demo question with common contact details removed, the requested language, and public evidence statuses. Official facts and links come from the catalogue. The server checks the coaching response for format, language and disallowed details before displaying it.
- The API validates the request shape, enforces a 6 KiB body limit and checks the browser origin. The chat uses a saved academic profile only when the applicant selects it in Context. The model prompt and quota store exclude the saved profile, CV, activity descriptions, essay drafts and prior question text. The demo coaching response is not cached. The older plan-only API uses a five-minute cache for non-personalized requests.
- Default AidMap budgets are 60 Groq attempts and 100,000 reserved tokens per 24-hour window plus six attempts per minute per caller (IP-based). Each attempted fallback consumes the same quota budget. Local development tracks limits in memory. Preview requires a shared Upstash Redis quota and cooldown. A provider-wide or ambiguous 429 stops the chain and observes Retry-After when supplied. Unavailable models, model-only limits, invalid model output and timeouts can try the next model. Authentication failures stop the chain. Adjust budgets using the limits of your own Groq organization.

## Groq review

As checked on 2026-11-22, Groq lists openai/gpt-oss-120b and openai/gpt-oss-20b as production models, and qwen/qwen3.8-27b as a Preview model for evaluation. AidMap uses them in the requested order for demos. Configure a Groq account that is on its free plan and check the model permissions and limits in that account. [Groq model catalogue](https://console.groq.com/docs/models) · [Groq rate limits](https://console.groq.com/docs/rate-limits)

Groq documents processing and retention separately for customer data. Inference inputs and outputs may be retained for up to 30 days for reliability or abuse investigations unless the applicable Zero Data Retention setting is enabled. Its privacy policy states that Groq’s own services are not directed to children. Given AidMap’s school-age audience, public deployments use catalogue mode. External inference is limited to authorized adults using synthetic profiles. Review the agreements and the intended audience before widening access. ## Local demo

1. Create a key in the [Groq Console](https://console.groq.com/keys) for a free-plan project with access to the listed models.
2. Copy the Advisor variables from [.env.example](../.env.example) into the existing .env.local, preserving existing app configuration. Set GROQ_API_KEY and ADVISOR_AI_MODE=demo. The three model variables may be omitted to use the defaults. Keep secrets server-side.
3. Run **pnpm dev --webpack** and open **http://127.0.0.1:3000/advisor**. In **Authorized AI demo**, confirm that you are an adult and allow Groq to process the synthetic demo question. Ask a comparison, roadmap or essay-planning question. A validated model response displays **Maple’s AI suggestion**.

## Vercel deployment

1. Deploy the updated branch as a **Preview** in the existing Vercel project. The repository’s install and build guard requires Preview, so use the existing branch/deployment workflow or run **vercel deploy** from the linked repo. On the publicly shared Preview leave ADVISOR_AI_MODE unset or set it to catalogue, with all Advisor credentials absent. Verify GET /api/advisor returns {"mode":"catalogue"} and that a question in /advisor returns source-linked results.
2. For a private demonstration use a separate **Preview deployment** and enable **Automatically expose System Environment Variables** if needed. Scope variables to Preview and, where available, only to the demo branch. Add ADVISOR_AI_MODE=demo, GROQ_API_KEY, and ADVISOR_DEMO_TOKEN (at least 32 random characters). Generate the token locally with **node -p "require('node:crypto').randomBytes(32).toString('hex')"**. Use Vercel’s secret type for credentials. Keep these values off the production environment and out of Git.
3. Add ADVISOR_REDIS_REST_URL and ADVISOR_REDIS_REST_TOKEN from an Upstash Redis free-plan database with a write-capable REST token. Leave its paid upgrades disabled. The preview shares its provider budget across instances through atomic Redis operations. Without working Redis the demo still provides catalogue answers. [Upstash free plan](https://upstash.com/pricing/redis) · [Upstash Redis REST API](https://upstash.com/docs/redis/features/restapi)
4. Redeploy the Preview so it picks up the variables. Share access only with authorized adult testers and have them enter the demo token in **Authorized AI demo** after confirming the checkbox. Use synthetic examples. Confirm the **Maple’s AI suggestion** label and official links. If absent, check account model permissions, API key validity, Redis connectivity and quota.
5. Redeploy with catalogue mode or remove the Preview secrets to close the demo. Keep public deployments in catalogue mode. [Vercel environment settings](https://vercel.com/docs/environment-variables/managing-environment-variables) · [Vercel system variables](https://vercel.com/docs/environment-variables/system-environment-variables)
